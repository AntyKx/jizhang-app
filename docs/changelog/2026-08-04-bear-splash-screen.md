# 開場儀式感畫面（參考 trip-planner 做法）

日期：2026-08-04

## 背景

使用者覺得另一個專案 trip-planner 的開場畫面效果很好，掃過那個專案的做法後發現：那不是靠資料讀取狀態的 `loading.tsx`，而是額外在根層級掛一個獨立的 `SplashScreen`，跟真實資料載入完全脫鉤——固定的進場/停留/淡出時間表，疊在最上層但設定 `pointer-events-none`，點擊事件會直接穿透到底下已經渲染好的內容，所以趕時間的使用者其實不會被真的卡住。使用者接著畫好 10 張新插畫（日常記帳、每週預算、採買記帳、旅行基金、共同帳本、每月帳單、咖啡日常、雨夜記帳、分類預算、儲蓄達標），要求比照這個做法做一版。

## 處理內容

- `public/images/bears/splash/`：10 張新插畫用 `sharp` 縮到寬度 560px、轉 WebP，每張約 60-85KB
- `src/components/bear-splash-screen.tsx`：從 trip-planner 的 `SplashScreen.tsx` 移植邏輯——冷啟動時從 10 張裡隨機挑一張，進場（放大 105%）→ 停留 1.45 秒（帶一道光澤斜向掃過）→ 淡出 0.6 秒，整段時間表跟真實資料讀完了沒完全無關（真實資料讀取仍然是 `loading.tsx` 在負責，兩者並存、互不影響）。`pointer-events-none` 讓使用者可以在動畫播放期間直接點穿到底下的畫面。
- 掛進 `src/app/layout.tsx`（根層級，放在 `<body>` 最後一個，DOM 順序上贏過其他 z-index 疊加的元素）——因為掛在根 layout、不是某個 Suspense 邊界，Next.js App Router 不會在頁面間切換時重新掛載 layout，所以只有真正的冷啟動（重新整理、PWA 開啟、第一次訪問）才會播放，App 內切換分頁完全不會觸發。
- 用一個暫時的 `/design-preview/splash` 頁面（可以逐張重播檢視）讓使用者在手機上確認效果，確認沒問題後已刪除，正式接進 production layout。

## 修正：有時候會連續跳出兩張圖片

使用者反應測試時偶爾會看到兩張開場圖連續播放。原因是根 layout 涵蓋 `/sign-in`、`/sign-up` 這些登入頁面，未登入時的完整路徑是：`/` → 轉址 → `/sign-in`（第一次播放開場動畫）→ 登入成功 → Clerk 導向 `/record`（部分登入流程是完整重新導航、不是單頁切換，所以根 layout 會重新掛載，開場動畫再播一次）。兩次都各自隨機挑一張，看起來就像連續跳出兩張不同的圖。

修正：開場動畫在 `/sign-in`、`/sign-up` 這兩個路徑直接不播放，只在真正進到 App 內容時（例如 `/record`）播放一次——也比較符合「歡迎進入」的語意，登入表單本來就不是使用者會停留欣賞畫面的地方。

## 修正二：已登入狀態單純重新整理還是會出現兩張

使用者實測後回報：不是登入流程的問題，是**已經登入的狀態下，單純重新整理/重開 App**，還是偶爾會連續看到兩張全螢幕開場圖。逐一排除了「正在部署觸發自動重新整理」（沒看到更新提示橫條）、程式碼裡重複掛載（確認 `layout.tsx` 只掛了一次）之後，沒能從程式碼直接找到根本原因是哪個瀏覽器/PWA 層級的機制讓根 layout 被重新評估了不只一次。

改用比較保險的做法：用 `sessionStorage` 記錄「這個分頁這輩子已經播過開場動畫」，不管背後是什麼原因讓元件又被掛載一次，只要這個標記存在就直接跳過，保證同一個瀏覽器分頁裡最多只播一次。**行為上的差異**：這代表如果你在同一個分頁裡重複重新整理測試，只有第一次會看到開場動畫，之後重新整理都不會再播（除非關掉分頁重開）——這是刻意的新行為，不是又壞掉了。

## 驗證

`tsc --noEmit`、`eslint`（改動檔案）、`next build` 全過，已用 `npx vercel --prod` 部署，使用者已在手機上實測確認效果。
