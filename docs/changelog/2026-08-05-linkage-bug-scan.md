# 全面掃描聯動邏輯缺口

日期：2026-08-05

延續昨天新增訂閱付款方式功能，使用者要求全面檢查有沒有類似的資料聯動缺口。逐一比對 schema、匯出/還原、跨功能資料流之後，找到並修好 2 個真的問題，另外記錄 1 個範圍較大、需要另外討論的功能缺口。

## 修好：訂閱分類選單沒有依類型篩選

`subscriptions/page.tsx` 查詢分類時變數叫 `expenseCategories`，但查詢本身**沒有加 `type = "expense"` 篩選**，等於把收入跟支出分類混在一起丟給新增/編輯訂閱的分類選單，而且切換「支出/收入」時也不會清空已選分類——跟 2026-07-31 那次「分帳支出分類選單出現收入類別」是同一種 bug，當時只修了分帳功能，訂閱這邊漏掉了。

修法：查詢改抓全部分類（含 `type` 欄位），`create-rule-dialog.tsx`／`edit-rule-dialog.tsx` 都改成依目前選的類型客戶端篩選，切換類型時清空已選分類——跟 `edit-transaction-dialog.tsx` 同一套已經驗證過的手法。

## 修好：備份/還原漏掉新欄位

備份/還原功能（`backup-schema.ts`、匯出 API、還原邏輯）是 7 月底寫的，昨天新增的 `recurringRules.paymentMethod` 欄位沒有跟著補進去——備份檔案不會包含付款方式，還原時會被重置成預設值「現金」。順便也發現 `sharedExpenses.settledAt`（分帳結清時間）從一開始就沒有被備份到。兩個都已經補上，`settledAt` 是時間戳記欄位，還原時要記得把 JSON 字串轉回 `Date` 物件，不能直接塞字串（型別檢查會噴錯，已修正）。

## 找到但先不動：訂閱沒有帳戶選擇器

`create-rule-dialog.tsx`／`edit-rule-dialog.tsx` 從頭到尾都沒有讓使用者選「這筆訂閱從哪個帳戶扣款」——永遠自動用 `getDefaultAccountId()`（第一個非排除淨資產的帳戶），而且編輯時也不能改。這代表多帳戶使用者剛剛才設定好的付款方式，實際上不一定對應到真正扣款的帳戶（例如設定信用卡自動扣款，但入帳時卻是從現金帳戶扣）。這是功能範圍比較大的缺口（要加帳戶選擇器 + 讓 `updateRecurringRule` 能改帳戶），不是一行修掉的 bug，先記錄下來，要不要做再討論。

## 確認沒問題的部分

- 逐一比對 `backup-schema.ts` 跟目前 schema.ts 的其他 6 張表，欄位都對得上（`categories.parentId` 沒被備份，但這個欄位從頭到尾沒有任何程式碼用到，是死欄位，不用管）
- 預算/儲蓄目標頁面沒有類似「分類沒依類型篩選」的問題（預算本來就只用支出分類，查詢已經有篩選；儲蓄目標沒有分類概念）

## 驗證

`tsc --noEmit`、`eslint`（改動檔案）、`next build` 全過，已用 `npx vercel --prod` 部署。
