# 新增開啟 App 的讀取畫面

日期：2026-08-03

## 背景

使用者反應開啟 App 時偶爾會一片黑，懷疑是不是當機了。查了一下，App 目前只有 `(app)/loading.tsx`（骨架屏，導覽列已經在畫面上，只有內容區塊顯示灰色方塊）跟幾個子頁面自己的 `loading.tsx`，但這些都只覆蓋「已經進到 App 殼層之後」的頁面切換。真正冷啟動的那一刻——Clerk 驗證身份、`(app)/layout.tsx` 查詢帳戶/分類資料這段時間——完全沒有任何畫面覆蓋，網路慢或伺服器冷啟動時就會整頁空白，看起來像沒反應。

## 處理內容

新增 `src/app/loading.tsx`（根層級的載入畫面）：置中顯示 App 圖示 + 「記帳本」文字 + 一條會來回滑動的漸層進度條（因為無法得知實際進度，用不確定進度條而不是假造一個百分比）。因為擺在最外層 `layout.tsx` 旁邊，Next.js 會把它當成整個 `(app)` 路由群組（含 `(app)/layout.tsx` 本身那段查詢邏輯）的載入邊界，涵蓋範圍比原本只包住頁面內容的 `(app)/loading.tsx` 更完整。

進度條動畫另外在 `globals.css` 加了 `@keyframes splash-progress-slide`，不動共用的 `Progress` 元件（那個是給預算/目標這種有實際百分比的地方用的，不想連帶影響外觀）。

## 已知限制

這個修法解決的是「Next.js 頁面資料還在讀取」那段空白，但沒辦法解決手機瀏覽器/PWA 在**任何網頁程式碼開始執行之前**那一瞬間的原生空白畫面（尤其 iOS PWA 沒有官方的啟動畫面機制）——那個更早的空白時間不是這次能處理的範圍，需要另外準備每個裝置尺寸的啟動圖片素材才能改善，這次沒有動。

## 驗證

`tsc --noEmit`、`eslint`、`next build` 全過，已用 `npx vercel --prod` 部署。
