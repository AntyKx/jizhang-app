# 掃 BUG：昨天右滑刪除統一化的副作用

日期：2026-08-02

## 掃描範圍

針對昨天（2026-08-01～02）新增的「全域 + 依情境帶預設值」跟「右滑刪除統一化」兩個改動重新檢查了一輪，同時確認了幾個原本擔心的可疑點其實沒問題（記在下面「排除的疑慮」）。

## 找到並修好的問題

**1. `RegularRow` 從按鈕變成純手勢區塊，鍵盤/滑鼠使用者少了操作方式**
昨天把 `/transactions`、`/accounts/[id]` 明細列表的一般交易列從原本真正的 `<button>`（滑鼠移過去有反白、Tab 鍵能focus、Enter 能觸發）換成 `SwipeToDelete` 純手勢包裝的 `<div>`，結果桌面滑鼠沒有反白提示，鍵盤也完全按不到。修法：`SwipeToDelete` 有 `onTap` 時自動加上 `role="button"`、`tabIndex`、滑鼠移過去反白、以及 Enter/Space 鍵直接觸發 `onTap`。

**2. 已結清的分帳項目仍然可以被 Tab 鍵選到**
`SharedExpenseRow` 傳給 `SwipeToDelete` 的 `onTap` 原本寫成「永遠是一個函式，內部才判斷 `!isSettled`」，導致上面第 1 點修好之後，已結清（不能編輯）的分帳項目也會被加上 `role="button"`/`tabIndex`，鍵盤使用者會 focus 到一個按下去沒反應的東西。改成已結清時直接把 `onTap` 設成 `undefined`，跟原本「已結清就拿掉 role/tabIndex」的邏輯一致。

## 排除的疑慮（檢查後確認沒問題，記錄下來避免以後重複懷疑）

**「跨頁面切換帳戶情境，FAB 的預設帳戶會不會卡住舊的」**：一度以為 `QuickAddCategoryFlow`／`PersonalAiQuickAddFlow` 裡靠 `useState(initialAccountId)` 只在掛載時算一次，如果元件在頁面切換時沒有重新掛載，預設帳戶會卡住舊頁面的值。查了 `@base-ui/react/drawer` 的文件確認 `Drawer.Portal` 預設 `keepMounted: false`——這個 App 的 `BottomSheet` 沒有覆寫這個選項，代表每次打開都是全新掛載，`defaultAccountId`／`defaultDate` 一定是當下最新的值，不是舊資料。

## 驗證

`tsc --noEmit`、`eslint`（改動檔案）、`next build` 全過，已用 `npx vercel --prod` 部署。
