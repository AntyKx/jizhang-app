# 共同帳本、全站補齊編輯功能、統計圖表新增、多項 UX 修復

日期：2026-07-25 ～ 2026-07-26

這次涵蓋好幾天累積的改動，主軸是「共同帳本」這個新功能從討論到落地，外加一輪全站編輯功能盤點、統計圖表擴充、以及幾個手機操作上的 bug 修復。全部已部署到 Production：https://jizhang-app-sand.vercel.app（`npx vercel --prod`，非 git 自動部署）。

## 一、共同帳本（情侶／共同支出分攤）

### 背景與範圍決策

一開始的需求是完整的「情侶共同帳本」：兩人各自登入、邀請機制、即時同步。討論後決定用 Clerk Organizations 做多人邀請（有現成的邀請 UI，不用自己刻），但實際設定時卡在 Clerk Dashboard 的 Membership 模式設定，使用者後來決定**先做單機版**——不需要真的邀請另一半登入，把「另一半」變成一個純顯示名稱（存在 `user_settings.partner_name`），付款人只有「我」跟「{另一半}」兩種選項。這個決定大幅簡化了架構：拿掉了 Clerk Organizations 相關的 `getOrgMembers`、`<OrganizationSwitcher>` 等程式碼，改成完全在 `requireUserId()` 底下運作。

### 資料模型

新增 `shared_expenses` 表（`userId`、`paidByMe: boolean`、`categoryId`、`name`、`amount`、`occurredAt`、`isSettled`、`settledAt`、`linkedTransactionId`）。`linkedTransactionId` 是關鍵設計：記帳時勾選「🤝 這筆算共同帳」，會同時在 `transactions` 插入一筆個人交易，並在 `shared_expenses` 插入一筆連結到該交易 id、`onDelete: cascade` 的紀錄——之後刪除那筆個人交易，共同帳那筆會自動一起消失，不會留下孤兒資料。

### 核心功能

- **新增共同支出**：手動表單 + AI 一句話快速記帳（`/api/shared-quick-add`，prompt 會帶入使用者設定的另一半名稱，讓 AI 判斷「我付的」還是「對方付的」，並支援相對日期）。
- **淨額結算**：不會真的叫兩人互轉兩次，直接算「淨差額」。逐筆結清會各自產生一筆結算交易；「一鍵標記已結清」則是把所有未結清項目軋平成**一筆**淨額交易（一開始做成每筆各開一筆，使用者回饋「一鍵結清應該只出一條」才改成現在這樣）。
- **結清會自動退款回個人帳**：這是這次討論出來、也是最重要的一個修正——結清一筆「我付的」共同支出，系統會在個人交易自動記一筆「收入」（代表對方把錢還我）；結清「對方付的」則記一筆「支出」（代表我把錢還對方）。金額是該筆的一半，備註固定是「共同帳結算：{項目名稱}」或「共同帳一鍵結清（共 N 筆）」，方便之後在其他統計裡辨識或篩選。沒有這個機制的話，個人支出統計會永遠停留在「結清前」的數字，看起來會跟現實兜不起來。
- **日期區間查詢**：新增起訖日期篩選（純 GET 表單 + URL 參數，沿用 `/stats` 頁既有的 searchParams 模式，不用額外前端狀態），篩選後未結清/已結清清單、淨額計算、「一鍵標記已結清」都只作用在篩選區間內，方便針對特定月份結算而不動到區間外的舊帳。
- **近 6 個月共同支出趨勢圖**：`/shared` 頁最下方新增一張堆疊長條圖（藍＝你、橘＝另一半），是跟「統計圖表要不要跟著擴充」討論出來的「輕量版」方案——不開新的統計分頁，只在共同帳本頁自己加一張小圖。
- **編輯與刪除**：未結清的共同支出可以點開編輯（項目/金額/分類/付款人/日期）；**已結清的項目不能編輯**，只能刪除重建——因為結清當下已經依原金額產生一筆個人收支，事後改金額會讓兩邊對不起來。

## 二、全站補齊編輯功能

使用者要求「掃一下整個系統，有哪些不能編輯的明細都加上去」，盤點結果與補齊項目：

| 位置 | 原本狀態 | 補的東西 |
|---|---|---|
| 已封存帳戶 | 只能取消封存 | 點卡片可編輯名稱/類型（沿用既有 `EditAccountDialog`） |
| 預算 | 只能新增 | 新增 `updateBudget`/`deleteBudget`，抽出 `BudgetsList` client component 承接編輯對話框 |
| 儲蓄目標 | 只能新增＋存錢 | 新增 `updateGoal`/`deleteGoal`，抽出 `GoalsList` |
| 所有交易（完整歷史列表，非今日明細） | 完全不能編輯 | 補上 `categoryId`/`accountId` 查詢欄位，沿用 `record` 頁的 `EditTransactionDialog` |
| 共同帳本明細 | 只能結清/刪除 | 見上一節 |

同時把「編輯交易」對話框裡的「商家」欄位拿掉（存檔時保留原值不動，只是不能再手動改），跟先前手動/AI記帳拿掉商家欄位的決定保持一致。

## 三、統計圖表新增

延續「統計圖表有沒有需要跟著這陣子改動增加」的討論，參考 Monarch Money / YNAB / Empower 等專業理財 App，`/stats` 總覽頁最上面（收支趨勢圖之前）新增兩張圖：

- **淨資產趨勢**：近 6 個月，所有帳戶餘額加總的面積圖。沒有存歷史快照表，是用「目前餘額」往回推算——每個帳戶的目前餘額，扣掉「該時間點之後」發生的所有交易增減，回推出當時的餘額。理論上準確（只要餘額異動都有經過 `transactions` 紀錄），但沒有實際資料驗證過。
- **金流圖（Sankey）**：左邊收入來源分類 → 中間「本期收入」節點 → 右邊支出分類，剩餘的錢流向「結餘」節點。用 recharts 內建的 `Sankey`（不用另外裝 `d3-sankey`），節點顏色沿用既有的分類色票。沒有收入時顯示提示文字；支出大於收入時不畫結餘那條線（負數沒辦法畫）。**這是專案第一次用 Sankey，節點的文字位置/顏色是照 recharts 型別定義手刻的，没有在瀏覽器裡實際看過渲染結果，需要之後找機會目視確認排版有沒有跑掉。**

## 四、Bug 修復

### 1. 新版本更新提示卡住不消失

`update-checker.tsx` 的 `useEffect` 依賴陣列裡放了 `reloading`，但 effect 內部又會呼叫 `setReloading(true)`——這會讓 React 重新執行這個 effect，重跑前的 cleanup 剛好把「即將重新整理」倒數計時器自己給清掉了，導致 `window.location.reload()` 永遠不會真的執行，banner 顯示出來後就卡住。修法：改用 `cancelled` flag 取代共用的 `timeoutId`，effect 依賴改成只看 `updateAvailable`。**這個 bug 存在於「舊版本」的前端程式碼裡，光部署新版沒辦法讓已經開著的分頁自己修好，需要使用者手動重新整理一次。**

### 2. Toast 通知擋住底部導覽 / 被動態島遮住

sonner 的 `<Toaster>` 沒設定位置，預設貼在畫面下緣，跟固定在底部的導覽列疊在一起；改成 `position="top-center"` 後又換成被 iPhone 動態島擋住。最終修法：`position="top-center"` + `offset`/`mobileOffset` 用 `env(safe-area-inset-top)` 往下推。

### 3. 底部導覽點兩次才有反應

導覽列 `fixed bottom-0` 完全貼齊螢幕最下緣，沒留 iOS 安全區域，跟系統「往上滑」手勢偵測區重疊，第一下點擊常被系統手勢吃掉。修法：導覽列加 `padding-bottom: env(safe-area-inset-bottom)`，內容區底部留白跟著加大；順手把全站共用的 `SlidingIndicator`（分頁切換背後會滑動的色塊）加上 `pointer-events: none` 防止意外擋住點擊。

### 4. 今日明細滑動時誤觸開啟編輯

手指滑動如果一開始帶一點斜角（很常見），`today-transaction-row.tsx` 會把它判定成「垂直滾動意圖」然後直接放棄處理，但沒有記住這件事；放開手指時因為沒被判定成「有效滑動」也没觸發長按，就被當成單純點擊，跳出編輯視窗。修法：新增 `verticalScroll` 標記記住這次手勢「有移動但不是滑動」，放開手指時看到這個標記就不處理。

### 5. 行事曆要點一次日期才顯示明細

`/calendar` 頁原本只有在 URL 帶 `?day=` 時才顯示當天明細。改成：沒有指定 `day` 且目前顯示的月份是本月時，預設帶入今天日期；切去其他月份則不會硬套「今天」（因為那天根本不在畫面裡）。
