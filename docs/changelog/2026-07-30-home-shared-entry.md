# 首頁加上「分帳記帳」入口

日期：2026-07-30

## 背景

首頁記帳欄位裡的「算分帳」開關，只能標記「自己付的錢也要跟另一半平分」（一定會建立一筆自己帳戶的交易）。真正的「分帳支出」流程（不動個人帳戶餘額，甚至可以記「另一半付的」）之前只有分帳頁（現在在更多裡）跟全域「+」的選單裡才有，首頁本身沒有入口。做了 3 個放置位置的預覽（AI 輸入列多一顆圖示／選擇分類旁邊加小按鈕／獨立卡片），選了「選擇分類旁邊加小按鈕」。

## 處理內容

- `record-screen.tsx`：「選擇分類」那行改成兩端對齊，右邊加一顆「分帳記帳」小按鈕（握手圖示），點下去彈出 `SharedQuickAddFlow`（跟分帳頁、全域「+」共用同一個元件，不是重做一份）
- 未解鎖核心功能時，點這顆按鈕會導去 `/upgrade?from=shared`，不會打開分帳流程——跟全域「+」的鎖定邏輯一致
- `record/page.tsx` 新增 `hasCoreAccess(userId)` 查詢，把結果當 `sharedLocked` 傳給 `RecordScreen`

## 驗證

`tsc --noEmit`、`eslint .`、`next build` 全過。已用 `npx vercel --prod` 部署，`/design-preview` 預覽頁已清掉。

## 更新：分帳記帳應該是原本的手動表單，不是語音/AI 那個

第一版接錯了元件——「分帳記帳」開下去的是 `SharedQuickAddFlow`（AI 文字/語音解析那套），使用者要的其實是分帳頁本來就有的**手動新增表單**（`AddSharedExpenseDialog`：項目/金額/日期/付款人/分類）。

`AddSharedExpenseDialog` 原本是自己管理開關狀態、自帶觸發按鈕（`DialogTrigger`）的獨立元件，只在分帳頁被使用。改成同時支援兩種用法：不傳 `open`/`onOpenChange` 就跟以前一樣（分帳頁維持原樣不受影響）；有傳的話就用外部控制的開關狀態，並且不渲染自己的觸發按鈕（因為呼叫端已經有自己的按鈕/選單去控制開關）。首頁的「分帳記帳」按鈕跟全域「+」的「分帳記帳」選項都改成用這個受控版本。

`tsc --noEmit`、`eslint .`、`next build` 全過，已部署。
