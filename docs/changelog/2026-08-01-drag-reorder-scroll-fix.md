# 修正：拖曳排序讓頁面變得難以往下滑

日期：2026-08-01

## 問題

帳戶管理頁面（`/accounts`）加上拖曳排序後，使用者回報往下滑變得比較困難。分類管理頁面（`/categories`）的拖曳排序用的是同一套機制，有一樣的問題。

## 原因

`SortableAccountCard`（`accounts-list.tsx`）跟分類格子（`category-sortable-grid.tsx`）的可拖曳元素上，都固定加了 `touch-none`（CSS `touch-action: none`）。這個屬性會讓瀏覽器從「手指一碰到這個元素」開始，就完全關閉這個元素原生的滾動能力——不管有沒有真的觸發拖曳，只要手指點在卡片上想往下滑，都會被擋下來。

先前為了修「太敏感」的問題，已經把拖曳觸發方式從「移動 8px 就觸發」改成「長按 250ms 才觸發」（`activationConstraint: {delay, tolerance}`），但當時保留了 `touch-none`，沒有意識到這個屬性本身就會擋住滾動，長按判斷邏輯再準確也沒用。

## 第一次修法（錯的，當天就改掉）

拿掉兩個元件上的 `touch-none`。結果使用者回報「變成不能移動帳戶卡片了」——`touch-none` 其實是 dnd-kit 的 `PointerSensor` 在觸控裝置上能穩定接管手勢的必要條件，拿掉之後瀏覽器的原生滾動會直接搶走手勢，長按判斷邏輯根本沒機會介入。

## 第二次修法（實際上線版本）

改成加一個獨立的「拖曳把手」（`GripVertical` 小圖示）：`touch-none` 跟拖曳的 `{...attributes} {...listeners}` 只放在這個小把手上，卡片/格子本體完全不帶任何拖曳綁定，所以本體隨便怎麼滑都是純原生滾動，只有真的抓住那個小把手才會觸發拖曳。把手獨立出來後，原本用來避免誤觸的「長按 250ms」也不需要了，改回近乎即時的 `distance: 4`，抓取更直覺。

帳戶卡片：把手放在帳戶名稱左邊。分類格子：把手放在格子左上角（跟右上角原有的刪除 X 對稱）。

## 驗證

`tsc --noEmit`、`eslint`（改動檔案）、`next build` 全過，已用 `npx vercel --prod` 部署。
