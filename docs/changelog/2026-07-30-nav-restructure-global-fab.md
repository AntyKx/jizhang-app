# 導覽列改版 + 全域快速記帳「+」

日期：2026-07-30

## 背景

延續前幾輪討論：想加一個到處都能用的快速記帳「+」，並趁機把導覽列重新配置——分帳搬到更多、帳戶升級成主分頁。先用 `/design-preview`（未連結頁面）做過視覺跟互動示意，這次是正式接上真正的資料跟功能。

## 處理內容

### 導覽列（`main-nav.tsx`）
- 「記帳」改名「首頁」（網址還是 `/record`，只改顯示文字跟定位）
- 「分帳」從主分頁移除，改到「更多」頁面裡（`more/page.tsx` 新增分帳連結，未解鎖時顯示鎖頭圖示，取代原本畫在導覽列圖示右上角的鎖頭）
- 「帳戶」從「更多」升級成主分頁
- 最終順序：首頁／行事曆／帳戶／統計／更多

### 全域快速記帳「+」（新增 `global-quick-add-fab.tsx`）
- 浮動在導覽列上方，`(app)/layout.tsx` 裡跟 `MainNav`一起渲染，所以每一頁都看得到
- 點下去彈出三選一：**一般記帳**（分類格→金額輸入）、**AI 記帳**（打字/語音一句話）、**分帳記帳**（跟另一半平分）
- 選哪個都是彈出一個蓋在當前畫面上的 sheet，不會真的換頁——記完關掉 sheet 還停在原本那頁
- 「分帳記帳」選項在未解鎖核心功能時顯示鎖頭，點下去導去 `/upgrade?from=shared`，不會真的打開分帳流程

### 重構（為了讓「+」能重用跟首頁一樣的記帳流程）
把 `record-screen.tsx` 原本內嵌的兩塊邏輯抽成獨立元件，首頁跟「+」共用同一套，不是各自維護一份：
- `quick-add-category-flow.tsx`：分類格 + 金額輸入 sheet（「一般記帳」）
- `personal-ai-quick-add-flow.tsx`：文字/語音/拍照的輸入列 + 對應的草稿編輯 sheet（「AI 記帳」）
- 分帳的 `SharedQuickAddFlow`（既有元件）加一個可選的 `onDone` prop，讓「+」用完可以關掉自己包的外層 sheet

首頁分頁（`RecordScreen`）現在只是組合這兩個抽出來的元件加上今日摘要、待繳訂閱、今天記帳列表，邏輯本身沒有變。

### 資料共用（新增 `src/lib/quick-add-context.ts`）
- `getQuickAddContext(userId)`：一次拿到分類、帳戶、另一半名稱，包成 `getDefaultAccountId` 的「新用戶自動建立帳本」邏輯也搬進來
- 用 React 的 `cache()` 包起來——`(app)/layout.tsx`（給全域「+」用）跟 `record/page.tsx`（首頁本身）在同一個請求裡都會呼叫到這個函式，`cache()` 確保同一個請求只真的查一次資料庫，不會因為 layout 跟 page 各自呼叫就查兩次

## 驗證

`tsc --noEmit`、`eslint .`、`next build` 全過。已用 `npx vercel --prod` 部署，`/design-preview` 預覽頁跟其專用元件已清掉。

## 更新：「+」縮小

首頁「今天記了 N 筆」列表的金額靠右對齊，跟浮動「+」的位置太近，會被擋到。按鈕從 56px（`size-14`）縮到 44px（`size-11`），圖示從 `size-6` 縮到 `size-5`，位置不變。已部署。

## 更新：首頁隱藏「+」

使用者反應首頁跟「+」彈出來的記帳畫面重複——首頁本來就有熊熊分類格跟 AI 文字/語音輸入列，這時候按「+」跳出來的是同一套流程，感覺是自己疊自己。熊熊圖不想拿掉，所以改成 `GlobalQuickAddFab` 用 `usePathname()` 判斷，網址是 `/record`（首頁）就直接不渲染這顆按鈕，其他頁面（行事曆、帳戶、統計、更多）維持顯示。首頁畫面完全沒變。已部署。
